The part I'm proudest of is the agentic loop I turned off

HireRadar: A Job-Search Pipeline That Remembers

View the Code on GitHub
Python Pipeline Gemini Decision Layer ChromaDB Semantic Scoring Memory-Aware Runs Resume-PDF Parsing SQLite + Streamlit Telegram Alerts

The Problem (Mine, Genuinely)

Senior-level job searching is broken, and searching for AI product roles makes it worse — the titles aren't even consistent yet ("AI PM", "Technical PM", "ML Product Owner"), and the right openings are scattered across LinkedIn, Naukri, CutShort, and niche boards.

My manual loop looked like everyone's: open four or five boards daily, scroll past noise, copy-paste a cover letter and change the company name, lose track of what I'd applied to, and miss good roles because I checked the board on the wrong day. HireRadar was built to replace that entire loop.

MVP 1 — Ship the Loop First (May 2026)

The first version was a straight pipeline, and I kept it deliberately dumb:

Search (LinkedIn + RemoteOK) → Deduplicate seen jobs → Score vs profile (0–100, keywords) → Filter at 65% threshold → Cover letters for 75%+ matches → Save to SQLite → Telegram alert with top matches

What I left out says more than what I put in: no Naukri or CutShort scrapers until two sources proved the value, no resume parsing, no scheduling (manual runs surface edge cases before automation hides them), no semantic scoring (keywords are inspectable), no feedback loop. The principle: ship the loop first, then make the loop smarter.

What MVP 1 Proved

  • The loop works end to end — search to alert to dashboard
  • Keyword scoring surfaces relevant roles well enough to start
  • Gemini cover letters are usable with minor edits
  • The Telegram alert built a daily habit around the tool
  • SQLite + Streamlit is plenty for personal tracking

Phase 1 Additions (June 2026)

  • Naukri + CutShort sources (WellFound blocked by Cloudflare — noted, moved on)
  • ChromaDB semantic scoring (all-MiniLM-L6-v2)
  • Resume PDF parsed automatically — one file update syncs scoring and cover letters
  • Per-job cover letters and targeted resume rewrites from the dashboard
  • agent_memory table — the system reads its own history before every run

The Decision I'd Put on a Whiteboard in an Interview

I built the full agentic orchestration loop — Gemini deciding every step, multi-turn. It worked. Then I built a leaner alternative and consciously set the impressive one aside.

Quota is a product constraint

The orchestration loop burned 5-8 Gemini calls per run deciding a sequence that never changes — 25-40% of the free tier's 20 daily calls spent on theatre. The lean version uses 2-4 calls total and leaves headroom for re-runs.

Reliability beats spectacle

One 503, one malformed function call, and the whole orchestration run died. The lean design has one decision call with a hardcoded fallback — the pipeline always completes. A tool I depend on daily doesn't get to be fragile.

Complexity has to earn its place

An orchestration loop earns its cost when the AI must make mid-run structural decisions. My sequence is always search → score → decide → cover → save → notify. Hardcoding it wastes nothing. The loop is preserved as the Phase 2 foundation, not deleted.

What the Smart Runner Actually Does

  • Reads the database history before each run and builds context for Gemini — including my written per-job feedback like "JD didn't align" or "service company".
  • One Gemini call returns structured decisions: which jobs to alert on, cover letter picks, threshold adjustments, companies to skip.
  • Adjusts the match threshold dynamically instead of using my fixed 65%, and can include a below-threshold role when it's from a target company.
  • Skips previously rejected companies with nuance — it reads why I rejected them, so a genuinely different role from the same company gets fresh judgment, not a blanket block.
  • Explains its reasoning in the Telegram message, and saves that reasoning to memory for the next run.

Is It "Agentic"? Honestly: Partially

It's memory-aware and it exercises judgment — thresholds, exceptions, skips — and it explains itself. But it has a single decision point with no reaction loop, no self-correction, no company research, and it doesn't infer patterns I haven't written down. The honest label is memory-aware pipeline with AI-assisted decision making. I'd rather under-claim and show the gap than call it an agent and hope nobody asks.

The Evolution Arc

MVP 1 (May 2026): hardcoded pipeline, keyword scoring, 2 sources, human decides everything.

Phase 1 (June 2026, live): memory-aware pipeline, semantic scoring, 4 sources, AI assists decisions — 1-3 Gemini calls per run.

Phase 2 (planned): six specialised agents — research, memory patterns, parallel search — where "AI assists" becomes "AI acts, human reviews". That's where the word "agentic" gets earned without qualification.

Known Limitations (kept honest)

  • LinkedIn scraping is fragile — accepted risk
  • No company research yet — cover letters start blind
  • No learning — scoring weights don't update from outcomes
  • Runs locally — deployment deferred until needed

Why This Is a Product Story, Not a Side Project

Problem first, AI second

The problem was defined before any AI entered. Gemini got the cover-letter job because personalized writing at scale is where it clearly wins; keywords got the scoring job in MVP 1 because they're debuggable.

Architecture as product decision

Choosing the lean runner over the orchestration loop was about quota budget, reliability, and delivered intelligence — not technical preference. I built both before choosing.

The human stays in the loop

The system surfaces, drafts, and explains. I apply, I update statuses, and my feedback becomes its context. It learns from my signal, not its own inferences.

Trust expands in stages

Manual run → memory-aware run → planned multi-agent run. Autonomy grows only as each layer proves itself — the same way I'd roll out AI in an enterprise.

The Short Version

HireRadar started as a weekend project to stop wasting time on job boards. MVP 1 proved the loop. Phase 1 made it smarter — four sources, semantic scoring, and one Gemini call that reads my application history and explains its decisions before the Telegram alert lands. The part I'm proudest of is the thing I turned off: a full agentic loop that worked, tested fine, and lost to a leaner design that makes the same decisions at a fraction of the cost. Phase 2 — research agents, pattern learning, parallel search — is where the system earns the word "agentic" without qualification. Each step is justified by what the previous one taught. That arc is the product story.

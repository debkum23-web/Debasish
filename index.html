Principles

AI amplifies judgment I already have — it doesn't fill gaps I don't have. In the Message Center platform, the LLM interprets a question but never touches the database directly; a separate API runs the query. In my capstone, ambiguous contract language returns a null with a rationale instead of an invented value. Same rule, every product: AI finds the pattern, a human makes the call.

Message Center Intelligence Platform — Product Owner & Principal Engineer

Approach

How I work.

Step 01

Start From the Decision, Not the Request

Leadership asked for a better email; the real spec was history, urgency, and ownership. My capstone schema began the same way — from the questions Legal and Sourcing actually ask, not from everything a contract contains.

Step 02

Wall the AI Off From the Data

In the Message Center platform, the LLM interprets the question but a separate search API runs it — that guardrail was in the first design, not bolted on, which is why security and compliance conversations went smoothly.

Step 03

Ask, Don't Guess

An ambiguous search query gets a clarifying follow-up, not a best guess. Ambiguous contract language gets a null with a rationale, not an invented value. Same rule, every product I build.

Step 04

Let AI Find the Signal, Keep the Call Human

Copilot classified 1,200 tickets in hours, but which features to build was my judgment. The capstone routes 23% of results to human review by design. I keep that boundary deliberate, and I ship into workflows people already use so adoption isn't a separate fight.

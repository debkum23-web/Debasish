Principles

My working rule is that AI should sharpen judgment I already have, not substitute for judgment I don't. In the Message Center platform, the LLM reads the question, but a separate API actually runs it against the database — it never touches the data directly. My capstone follows the same logic: ambiguous contract language returns a null with a reason instead of a guess. Different products, same rule. AI surfaces the pattern, I make the call.

Approach

How I work.

Step 01

Find the Real Decision Behind the Ask

Leadership asked for a better email. What they actually needed was history, urgency, and clear ownership on each item. My capstone schema started the same way, working backward from the questions Legal and Sourcing actually ask instead of trying to capture everything a contract contains.

Step 02

Keep the AI Away From the Data Itself

In the Message Center platform, the LLM only interprets the question. A separate search API runs it against the database, so the model never touches the data directly. That wall was there from the first design, which is a big part of why the security and compliance conversations went smoothly.

Step 03

When Something's Ambiguous, Ask

If a search query is ambiguous, the system asks a follow-up instead of guessing. If contract language is ambiguous, it returns a null with a reason attached instead of making something up. Same rule, showing up in two different products.

Step 04

Let AI Surface the Signal, Keep the Decision Human

Copilot classified 1,200 tickets in a few hours, but deciding which features to actually build was still on me. My capstone routes about 23% of its results to human review by design — that boundary is deliberate. I also try to ship into workflows people are already using, since that's most of why adoption happens at all.

Flagship Project — Owned End-to-End

Message Center Intelligence Platform

Product Owner & Principal Engineer — from data model to production dashboard, now used firm-wide

Product Ownership LLM-Driven Search Microsoft Graph APIs SQL Schema Design Angular Dashboard Jira Automation Azure AD Governance

Context

Microsoft 365 Message Center advisories drive real work — deprecations, security changes, compliance deadlines. Scrum masters, product owners, and leaders across the firm depend on catching the right ones in time.

Problem

A scheduled script sent one daily email digesting the last 24 hours — no historical view, and no way to separate a critical advisory from routine noise. Important messages got lost in the inbox; the messages that mattered most were easiest to miss.

The Product Decision

I decided a better email wasn't the fix. The real gaps were historical, queryable access; visual separation of what matters; and a traceable owner for every action item. That framing shaped every build decision that followed.

Users & Stakeholders

Scope Owned

How It Was Built

Scheduled Ingestion & Queryable Schema

A console application pulls Message Center data from Microsoft APIs into a SQL database on a schedule. The schema was designed for historical, queryable access — not raw archiving — so every past advisory stays searchable.

API Layer + Angular Dashboard

A custom API layer of 18 endpoints feeds an Angular dashboard where important messages are flagged and visually separated at the top — the gap the daily email never closed.

LLM Search with Clarifying Follow-ups

When filtering wasn't enough, I added natural-language search: an LLM interprets the query and asks a clarifying follow-up when intent is ambiguous. A separate search API — never the LLM — queries the database. Separation of duties by design.

One-Click Jira Creation

Flagged messages get one-click Jira tickets, auto-populated from message data, with the Jira number surfaced back in the UI — replacing manual copy-paste with a traceable owner for every action item.

Identity-Governed Access

Azure AD login with a UPN-to-permissions mapping controls dashboard visibility — access governed by identity, not a bolt-on login screen.

Product Ownership in Practice

  • Reframed the problem: rejected "improve the email" in favor of the real unmet needs — history, signal separation, and traceability.
  • Sequenced the roadmap by user value: queryable data first, then visual triage, then NL search, then Jira traceability — each release usable on its own.
  • Designed AI responsibly: the LLM interprets intent and asks clarifying follow-ups, but never touches the database directly — guardrails as a product requirement, not an afterthought.
  • Made governance a feature: Azure AD identity mapping means access control is auditable by design.
  • Closed the loop: every flagged advisory can become a tracked Jira ticket with a visible owner.

Key Takeaways

This platform is what AI-native product ownership looks like in practice: start from the user's real gap (signal lost in noise), design the data layer for the questions people actually ask, add an LLM only where language understanding genuinely helps — with strict separation of duties — and make every insight traceable to an owner. The result replaced a daily email nobody trusted with a system the whole firm relies on, while cutting support demand by 30% and keeping audit compliance at 100%.

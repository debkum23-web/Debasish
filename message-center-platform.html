Flagship Project — Owned End-to-End

Message Center Intelligence Platform

Product Owner & Principal Engineer — from data model to production dashboard, now used firm-wide

Product Ownership LLM-Driven Search Microsoft Graph APIs SQL Schema Design Angular Dashboard Jira Automation Azure AD Governance

Context

Microsoft 365 Message Center advisories create real work: deprecations, security changes, compliance deadlines. Scrum masters, product owners, and leaders across our firm all need to catch the right ones in time.

Problem

What we had was a scheduled script that sent one email a day summarizing the last 24 hours. There was no history, and a critical advisory looked exactly like routine noise. People missed things. The messages that mattered most were the easiest to lose in an inbox.

The Product Decision

The obvious ask was "make the email better." I didn't think that was the fix. When I talked to the people reading it, the actual gaps were different: they couldn't look anything up after the fact, they couldn't tell at a glance what was urgent, and nothing connected an advisory to a person responsible for acting on it. Those three gaps became the spec.

How It Was Built

Scheduled Ingestion & Queryable Schema

A console app pulls Message Center data from Microsoft's APIs into SQL on a schedule. I designed the schema around the questions people actually ask ("when did this change?", "what else affected this service?") rather than just archiving raw payloads, so every past advisory stays searchable.

API Layer + Angular Dashboard

I built an API layer — 18 endpoints — feeding an Angular dashboard. Flagged messages sit at the top, visually separated from everything else. That one design choice fixed the thing the daily email never could.

LLM Search with Clarifying Follow-ups

Once people had history, filters stopped being enough. So I added natural-language search: an LLM interprets the question, and if it's ambiguous it asks a follow-up instead of guessing. The LLM never touches the database — a separate search API runs the actual query. I wanted that separation from the start.

One-Click Jira Creation

Any flagged message can become a Jira ticket in one click, pre-filled from the message data, with the ticket number shown back in the dashboard. Before this, tracking an advisory meant copy-pasting into Jira by hand — or more often, not tracking it at all.

Identity-Governed Access

Login goes through Azure AD, and a UPN-to-permissions mapping decides what each person sees. I didn't want a bolt-on login screen; access control had to come from identity so audits could verify it.

Firm-Wide Adoption

Scrum masters, product owners, and leaders across the firm use it now. The daily email is gone, and nobody has asked for it back.

What I'd Point To as Product Work

  • Saying no to the stated request. Everyone wanted a better email; the job was to figure out why the email could never work and build for that instead.
  • Sequencing by usefulness. Queryable data shipped first, then visual triage, then the NL search, then Jira integration. Each release stood on its own — if the project had stopped at any point, people would still have had something better than before.
  • Deciding early that the LLM would never query the database. That guardrail was in the first design, and it made every later conversation with security and compliance easier.
  • Treating governance as a feature rather than a checkbox. Identity-based access meant auditors could verify who saw what without asking us.
  • Closing the loop from "advisory noticed" to "ticket with an owner." That's the part that changed behavior, not just visibility.

Key Takeaways

The biggest lesson from this project wasn't technical. It was that the request people bring you ("fix the email") is usually a symptom, and the real product work is naming the actual gaps and building for those. The AI part came last, and only where it earned its place — language understanding for search, with a hard wall between the LLM and the data. What we ended up with replaced an email nobody trusted with a system the whole firm relies on, cut support demand by 30%, and kept us at 100% on audits. I'm more proud of the fact that nobody wants the old email back than of any single feature in it.
